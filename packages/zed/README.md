# x18n for Zed

The Zed extension starts `@x18n/lsp` and passes Zed settings to the language server. i18n analysis stays in the LSP package. The Zed registry extension path is `packages/zed`. The registry builds WASM from source.

## Develop locally

Use Node.js 22+, Rust stable with `wasm32-wasip2`, and Zed's extension API 0.7.

```sh
pnpm install
cd packages/zed
rustup target add wasm32-wasip2
cargo build --release --target wasm32-wasip2
```

In Zed, choose **Extensions → Install Dev Extension** and select `packages/zed`. Grant `npm:install` for `@x18n/lsp` and `process:exec` for Node when prompted. `extension.wasm` is generated by Zed and must not be committed.

The package checks are `pnpm test`, `cargo test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo build --release --target wasm32-wasip2`. Node tests use `node --test` against the published `@x18n/lsp`. Rust tests cover the extension's server selection. [Editor smoke checks](./docs/e2e-smoke.md) remain manual.

## Language server selection

| Priority | Source | When |
| --- | --- | --- |
| 1 | `lsp.x18n.binary` | Explicit command override |
| 2 | `<worktree>/node_modules/@x18n/lsp/bin.mjs` | `useLocalServer` is true (default) and the project has the package |
| 3 | `npx -y @x18n/lsp@<serverVersion> --stdio` | `useNpx` is true and `npx` is on `PATH` |
| 4 | Extension-managed npm install | Otherwise. Installs `@x18n/lsp@<serverVersion>` |

`serverVersion` defaults to `latest`. Set it to a version to pin the npx and extension-managed server. The extension sends `worktreeRoot` in LSP initialization options. See [workspace-folder notes](./docs/workspace-folders.md).

## Zed settings

Add settings to the user or project `.zed/settings.json`:

```json
{
  "lsp": {
    "x18n": {
      "settings": {
        "useLocalServer": true,
        "useNpx": false,
        "displayLocale": "",
        "annotationMaxLength": 40,
        "codeLens": false,
        "showFlags": true
      }
    }
  }
}
```

The extension covers JavaScript, JSX, TypeScript, TSX, Vue.js, JSON, JSONC, YAML, HTML, Svelte, and Astro. Zed exposes the server's hover, navigation, rename, completion, diagnostics, code actions, and hints. A hover is the locale table and a usage count.

## Release

The extension version in `extension.toml` follows the x18n release: `pnpm release` (bumpp) bumps it with the npm packages, and the `v*` tag runs the `zed` job in [`release.yml`](../../.github/workflows/release.yml). That job opens a pull request on [`zed-industries/extensions`](https://github.com/zed-industries/extensions) that moves the registry to the new tag, and skips releases where nothing in `packages/zed` changed. Zed merges the pull request and its CI builds and publishes the extension.

The first submission to the registry is manual. Later releases need the `ZED_COMMITTER_TOKEN` secret and the `x18n-dev/zed-extensions` fork.
