The `apple-strings` preset supports [string catalogs](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog) (`.xcstrings`), `.strings` files and `.stringsdict` files on iOS and macOS.

## Detection

The preset applies when the project has a `.xcstrings` file, or `*.lproj/*.strings` or `*.stringsdict` files.

```ts [x18n.config.ts]
import { defineConfig } from '@x18n/core'

export default defineConfig({
  presets: ['apple-strings'],
})
```

## Locale files

A catalog `{table}.xcstrings` holds every locale in one file. A key with no source text is its own text, as in Xcode, `shouldTranslate: false` is not a message, a write sets the state to `translated`, and the file keeps Xcode's layout. To add a language, add it in Xcode or list it in `locales`.

Plural variations are `key.one`, as in `.stringsdict` files, and device variations are `key.device.iphone`. A key's comment is the description of its messages, and a rename moves the key with every locale and its comment.

The other files are `{locale}.lproj/{table}.strings` and `{locale}.lproj/{table}.stringsdict`, skipping `Pods`, `Carthage`, `DerivedData` and `build`. `Base.lproj` is the source locale. The file name is the namespace, and `Localizable` is the default, so `Settings:theme` is `theme` in `Settings.strings`.

Keys are often whole sentences, so nothing in a key is a separator. In a `.strings` file, a comment right above an entry, with no blank line between, is its description for translators. A message of a `.stringsdict` file is a plural form, such as `items.one`.

## Supported syntax

<!-- eslint-skip -->

```swift [ContentView.swift]
NSLocalizedString("title", comment: "")
NSLocalizedString("theme", tableName: "Settings", comment: "")
String(localized: "title")
String(localized: "theme", table: "Settings")
LocalizedStringResource("title")
Text("title")
Button("save") { }
"title".localized
```

In Objective-C, `NSLocalizedString(@"title", @"")` and `NSLocalizedStringFromTable(@"theme", @"Settings", @"")`. SwiftUI's `Text`, `Button`, `Label`, `Toggle` and `Link` take a key, so text written directly in them counts as one. In a key, `\(x)` becomes `%@` or `%lld` by its type at compile time, so `items \(n)` counts as a prefix, and the keys starting with `items ` are not unused.

## Placeholders

`%@`, `%d`, `%1$@`.
